# Residual-Profile Labeling

This note records the current stable implementation direction for the nested residual-profile pricing experiments.

## Stable Module

The reusable implementation is in `src/model/residual_profile_labeling.py`.

It provides:

- `ResidualProfileInstance`: one layer or sub-pattern instance with nested residual capacities and placement choices.
- `PlacementChoice`: one feasible component placement, represented by the nested resources it hits and its effective loading length.
- `ProfileLabelingOptions`: EX, GR, or HYB expansion mode.
- `solve_residual_profile_labeling`: residual-profile label expansion with local skyline and quantity-skyline pruning.
- `compare_profile_maps`: profile-coverage comparison against an EX reference.

## Expansion Modes

`EX` enumerates every feasible placement choice for each automobile type and quantity.

`GR` keeps only the outermost feasible choice on each side. This is exact only when every discarded placement is weakly dominated by one retained outer placement, meaning the retained choice hits a subset of nested regions and has no larger effective loading length.

`HYB` applies the GR placement reduction only to automobile types satisfying the above condition and keeps EX expansion for the remaining types. Under this condition, HYB has the same profile coverage as EX.

## Pruning

Local skyline pruning removes dominated residual profiles generated by the same extension.

Quantity-skyline pruning removes dominated residual profiles within the same quantity vector and is safe for full pattern enumeration.

Reduced-cost label dominance is intended for pricing with a fixed continuation structure. It should not be used as a replacement for quantity-skyline pruning when generating the full pattern set for a master problem, because it may delete columns that are still needed by the master.
